## 0. Контекст и цель

Построить интернет-магазин ювелирного бренда **СИНОНИМ**: серебро с выращенными (лабораторными) бриллиантами. Позиционирование — современная демократичная ювелирка, эко-технологичность с женственным акцентом. ЦА: девушки 20–40. Средний чек ~25 000 ₽. Каталог ~200 SKU. Есть физический шоурум. Нужен полноценный онлайн-чекаут с оплатой.

**Стек (фиксирован):** Medusa v2 (backend) + Next.js 15 App Router (storefront, SSR/SSG) + TypeScript + Tailwind CSS v4 + Postgres. Деплой — позже, сначала рабочий локальный билд.

**Окружение:** разработка на Windows. Postgres (и Redis, если потребуется Medusa) поднимать через Docker Compose — это надёжнее, чем нативная установка на Windows. Все команды давай в формате, рабочем под Windows/WSL.

**Принцип:** не усложнять. 200 SKU и чек 25k — это небольшой проект, без оверинжиниринга. Не выдумывай интеграции, которых нет (см. фазу 5): где нет готового решения — делай абстракцию с понятными TODO, а не фейковую реализацию.

## 1. Бренд (зашить в дизайн-систему)

Знак «О» в логотипе — это круглая огранка бриллианта (ключевой визуальный мотив, можно переиспользовать как декоративный элемент/иконку).

**Палитра (финальная):**
```css
@theme {
  --color-brand:       #73A341; /* оливковый — бренд, лого, акценты */
  --color-brand-dark:  #4A5335; /* тёмный оливковый — текст-акцент, кнопки, хедер/футер */
  --color-accent:      #D47750; /* терракотовый — детали, hover, бейджи */
  --color-accent-deep: #C96A4A; /* терракотовый тёмный — акцент на светлом */
  --color-sand:        #E8D9B5; /* песочный — мягкие подложки, секции */
  --color-bg:          #FBF8F1; /* тёплый кремовый фон страниц */
  --color-surface:     #FFFFFF; /* карточки товара, инпуты */
  --color-ink:         #1A1A1A; /* основной текст */

  --font-display: "Playfair Display", Georgia, serif; /* заголовки */
  --font-body:    "Inter", system-ui, sans-serif;     /* основной текст */
}
```

**Доступность (обязательно соблюдать):** яркий `brand`/`accent` на белом НЕ проходят WCAG AA для мелкого текста. Поэтому: CTA-кнопки — фон `brand-dark` + белый текст; терракотовый — только как акцент/деталь или фон под тёмный текст `ink`. Заголовки — `brand-dark`, не `brand`.

**Шрифты** — через `next/font/google`, оба с сабсетами `["latin","cyrillic"]`, `display: "swap"`, как CSS-переменные `--font-display` / `--font-body`. Playfair Display weight 400/600/700, Inter 400/500/600.

**Логотип:** держать 3 SVG-версии (цветной — основной, чёрный — на светлом, белый — на тёмном). Мин. ширина на экране 80px. Защитное поле вокруг ≥ высоты знака «О». Запрещено: менять пропорции, тени/градиенты/обводки, перекрашивать, наклонять/обрезать. На пёстром фоне — только одноцветная версия. (Сами файлы лого я подложу в `/public/logo/` — оставь импорты и заглушки.)

## 2. Модель данных каталога

Продукт = модель украшения. Варианты (Medusa variants/options) = комбинация:
- **размер** (кольца/браслеты),
- **каратность вставки** (выращенный бриллиант, напр. 0.1 / 0.2 / 0.3 ct),
- **металл/проба** (серебро 925).

Цена задаётся на вариант → на карточке и в листинге показывать **«от {min цена по вариантам}»**, если вариантов с разной ценой несколько; иначе фиксированную цену.

**Кастомные поля** (через Medusa module / metadata):
- `uin` — УИН ГИИС ДМДК на уровне конкретного физического изделия (инвентарной единицы). Нужен на чекауте и для синка остатков. Заложи как поле инвентарной позиции/варианта.
- `stone`: тип камня (`lab-grown-diamond`), вес (ct), огранка, цвет/чистота (для будущего JSON-LD и фильтров).
- `metal`: `silver-925`.

Регион/валюта: **RUB**, локаль `ru-RU`, цены в рублях. Налог — заложить ставку, значение уточню.

Категории под навигацию: Кольца, Серьги, Подвески и колье, Браслеты, Помолвочные кольца. Фильтры: каратность, огранка, размер, цена, металл — через URL-сегменты.

Сделай seed-скрипт с ~12–15 демо-SKU (реальные 200 зальём позже), чтобы storefront был наполнен для разработки.

## 3. Фазы сборки

### Фаза 0 — инициализация
- Поднять Postgres (+Redis при необходимости) через Docker Compose.
- Развернуть Medusa v2 backend (`create-medusa-app` или ручная инициализация v2) и официальный Next.js Starter для storefront как отдельное приложение, связанное с backend по Store API / publishable key.
- Tailwind v4 в storefront, подключить `@theme` из раздела 1.
- **DoD:** backend поднимается, admin доступен, storefront рендерит главную-заглушку с брендовой темой и шрифтами.

### Фаза 1 — backend и каталог
- Регион RUB, модель вариантов из раздела 2, кастомные поля `uin`/`stone`/`metal`.
- Seed-скрипт с демо-SKU и категориями.
- **DoD:** товары с вариантами и разными ценами видны в admin и отдаются Store API; «от {min}» вычисляется корректно.

### Фаза 2 — storefront
- Layout: хедер (лого, навигация по категориям, поиск, корзина, избранное), футер (Покупателям / О бренде / Контакты / соцсети), sticky-бар на мобиле (телефон + шоурум).
- Главная: лёгкий hero (см. фазу 3 — без тяжёлого autoplay-видео в LCP), блоки коллекций, преимущества (выращенные бриллианты, сертификаты, шоурум).
- Листинг категории: сетка карточек, фильтры через URL-сегменты, ленивая загрузка изображений (`next/image`, webp/avif).
- Карточка товара: галерея, выбор варианта (размер/каратность) с пересчётом цены, «в корзину», «в избранное», блок характеристик камня, доставка/гарантия, ссылка на проверку УИН.
- Корзина + страница оформления (UI).
- Эстетика: refined/minimal, премиальная доступность; Playfair в заголовках, мотив огранки «О» как деталь; не «AI-шаблон».
- **DoD:** можно пройти путь главная → категория → фильтр → карточка → корзина; адаптив; Lighthouse-перформанс мобайла зелёный на главной и листинге.

### Фаза 3 — SEO (сделать лучше конкурента lavivion.ru)
- **JSON-LD** на каждой сущности: `Product` + `Offer` (цена, валюта RUB, наличие), `BreadcrumbList`, `Organization`, `WebSite`. Это главный приоритет — у конкурента этого нет.
- Корректные `<title>`/`meta description` без двойного экранирования (никаких `&amp;#...`), гео-модификаторы где уместно.
- `viewport` БЕЗ `maximum-scale=1` (доступность).
- Канониклы: фильтр-страницы канониклятся на родительскую категорию; многопараметрические комбинации — `noindex` либо canonical на родителя (без индекс-мусора).
- Блок «Рекомендуемые подборки» — ручная перелинковка на одиночные фильтры под длинный хвост (каратность/огранка/размер/металл).
- `sitemap.xml` + `robots.txt`, OpenGraph/Twitter-теги, hreflang `ru-RU`.
- **DoD:** Rich Results Test проходит для Product/Breadcrumb; нет дублей в каноникал-логике; sitemap валиден.

### Фаза 4 — чекаут и платежи
- Medusa v2 **payment provider module** под российский эквайринг (ЮKassa или Т-Касса). Реализовать интерфейс провайдера (initiate/authorize/capture/refund/webhook), вынести ключи в env. Если готового community-модуля под v2 нет — писать свой по официальному гайду Medusa по payment provider.
- Поток оформления: адрес/доставка → способ оплаты → редирект/виджет эквайринга → webhook подтверждения → статус заказа.
- **DoD:** заказ создаётся, уходит в эквайринг (sandbox), webhook переводит заказ в paid. Боевые ключи — на мне.

### Фаза 5 — комплаенс-слой (КРИТИЧНО, без фейков)
Ювелирка в РФ: продажа маркированного товара обязана проходить через фискализацию (54-ФЗ) и транспортный модуль ГИИС ДМДК с УИН в чеке, с онлайн-проверкой статуса УИН до пробития чека. **Готового плагина под Medusa нет.** Поэтому:
- Создать **абстрактный сервис `FiscalizationService`** с методами `checkUIN(uin)`, `registerSale(order)`, `sendReceipt(order)` и явными `TODO` под конкретного провайдера облачной кассы с поддержкой ювелирки/ГИИС ДМДК (АТОЛ Онлайн / Бизнес.Ру / Модулькасса / ЕКАМ — провайдер выберу отдельно).
- На этапе создания заказа: хук, который проверяет наличие `uin` у позиций и блокирует оформление, если УИН отсутствует/невалиден (заглушка проверки → потом реальный вызов ТМ).
- НЕ имитировать успешную фискализацию. Если интеграции нет — оставить заказ в статусе `pending_fiscalization` и логировать TODO.
- **152-ФЗ:** cookie-баннер с явным согласием; страница «Политика обработки ПДн»; чекбоксы согласия во всех формах (заказ, обратный звонок, подписка) с ссылкой на политику; не отправлять форму без согласия.
- Страницы: Доставка, Оплата, Гарантия, Возврат, Сертификация камней, Юридическая информация (с реквизитами и ссылкой на проверку в ГИИС ДМДК), Контакты/Шоурум (карта, адрес, часы).
- **DoD:** заказ с товаром без УИН не оформляется; формы не отправляются без согласия; все юр-страницы доступны по прямым URL (проверь, чтобы не было 404 как у конкурента).
